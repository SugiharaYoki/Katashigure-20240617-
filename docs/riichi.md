# 立直麻将

目标版本：原版 Java 1.21.11，无需插件或资源包。入口隐藏，不接入多功能菜单、赌场接待员或快捷操作。

更新数据包后执行 `/reload`。普通玩家使用：

```mcfunction
/trigger Mahjong set 1
```

打开大厅，可创建四人／三人、东风／半庄房间，或点击房间加入。共四间独立房间；房主可以补齐或移除人机，也可以与其他玩家混合对局。开局后不能再加入。人机仅显示座位编号，不展示性格。

```mcfunction
/trigger Mahjong set 2
```

返回自己的牌桌。收起面板保留座位。出牌直接点击牌面；立直先点「立直」，再选择宣言牌。荣和、自摸、吃碰杠、拔北使用对应按钮；未满足规则的操作会被服务端拒绝。吃左／中／右表示所吃的弃牌在顺子中的位置。

## 资金

使用现有 `Perm_PersonFSB` 浮世币账户，**1 FSB = 1 点**。四麻买入 25,000 FSB，三麻买入 35,000 FSB，买入前显示确认页。取消、余额不足、房间已满或已开局均不扣款。人机使用赌场资金。

等待开局时离桌立即退款。比赛中申请离桌或离线后由人机代打，整场结束按剩余点数兑回；不能在一局中途提走点数。支付上限为付款人的托管点数，点数归零立即结束比赛，不透支钱包。无顺位马点、头名奖励或额外手续费。

退款按 UUID 记账，离线玩家重新上线自动领取，跨 `/reload` 保留，不重复退款。钱包达到记分板整数上限时，未能存入的部分保留在待领账本。麻将与德州席位互斥；带 `Gaming` 标签的玩家不能买入。

## 本桌规则

- 四麻 136 张；三麻 108 张，移除二至八万，禁止吃牌，可拔北，采用自摸损。三麻北作通常字牌或拔北宝牌，拔北每张加 1 番；北同时是宝牌时叠加计数。拔北补牌不算岭上，可形成海底；拔北会打断一发与首巡役。
- 门清立直需至少 1,000 点且牌山剩至少 4 张。支持两立直、一发、立直后摸切；暗杠必须是刚摸到的第四张，听牌集合和面子解释均保持不变。宣言牌被荣和时立直不成立，退回本次供托。
- 支持常用役种、七对子、国士、役满与复合役满；番符计算、满贯至役满封顶。宝牌、赤宝牌、里宝牌和拔北宝牌本身不能提供和牌所需的役。无食替，允许食断；连风雀头计 4 符。双倍役满按单倍计，累计役满封顶单倍，无切上满贯。
- 自弃振听检查全部听牌和完整牌河，被鸣走的弃牌仍计入。放弃荣和产生同巡振听，下一次摸牌解除；立直后放弃荣和持续振听至本局结束。
- 荣和优先于碰杠，碰杠优先于吃；碰杠冲突按离放铳者的座次顺序处理。支持多家荣和；四麻三家荣和流局。加杠可抢；暗杠和拔北仅允许国士抢和。
- 荒牌根据最后一次出牌缓存的听牌结果结算：四麻不听罚符池 3,000 点，三麻 2,000 点。庄家和牌或听牌连庄；流局增加本场。包含九种九牌、四风连打、全员立直、四杠散了和三家荣和等途中流局。
- 东风打东场，半庄打东、南场；末局连庄可以继续，轮庄后结束。无南入／西入、和了止或听牌止。终局剩余供托归最高分者，同点按席位先后。此版本不采用流局满贯、包牌责任或地方役。

每次出牌 30 秒，鸣牌响应 15 秒。人机约 2 秒行动；普通玩家连续两次出牌超时后交由人机代打。房主离线或申请离桌会移交房主；全体离线时仍会自动完成比赛并记账退款。人机使用自己的手牌与公开牌河，不读取对手手牌或未来牌山。

## 界面与实现

牌桌分为房间概况、固定列宽的座位点数、宝牌与公开牌河、自己的手牌、行动按钮。万／筒／索分别着色，新摸牌单独标记；结算展示和牌、役种、番符及各人的本局增减。终局保留最终座位表，其他玩家离线不影响查看结算。

`storage skyblock:mahjong` 保存牌山、四间房间、回合状态与 UUID 退款队列。`mj` 为内部记分项，`Mahjong` 为普通玩家 trigger；`MahjongRoom`、`MahjongSeat` 记录座位。每次操作校验 UUID、行动座位与牌桌版本号，过期按钮不会重复出牌或扣款。未公开手牌只发给该座位的真实玩家。

生成源在 `tools/riichi_codegen/`，运行 `python3 -B tools/generate_riichi.py` 更新数据包函数。服务端无需 Python。座位表复用 `tools/holdem_codegen/layout.py` 的原版 `minecraft:uniform` 字宽表。

## 验证

`tools/validate_riichi.py` 使用独立的 [MahjongRepository/mahjong](https://github.com/MahjongRepository/mahjong) 规则库生成原版服务端测试，覆盖多解牌形、役种支付、听牌、吃碰杠、抢杠、抢北、振听、立直成立与撤销、多家荣和、自摸、流局罚符和托管支付上限。

```sh
python3 -B tools/validate_riichi.py \
  --oracle-path /path/to/mahjong-checkout \
  --output /path/to/isolated-test-pack/data/riichi_test/function
```

如果已安装 `mahjong` Python 包，可以省略 `--oracle-path`。在隔离的 1.21.11 测试服 `/reload` 后，先执行 `function riichi_test:reset`，再分别执行生成的 `manifest.json` 中的每个函数。检查 `#validation_failed mj` 为 0、`riichi_test:results failures` 为空。测试会改写内部工作区和 99 号测试房间，**只可在隔离测试服运行**，不应合并到生产数据包。

本次在原版 1.21.11 服务端通过 1,114 组测试（576 组番符／支付、400 组随机牌形、100 组独立听牌对照、38 组状态与结算场景）。四种模式共完成 29 局整场模拟，检查牌张数量和点数守恒；另验证四间房同时自动运行。普通非 OP 协议客户端验证了买入与取消、满房拦截、人机替换、私牌权限、伪造席位、过期按钮、多人响应、重载续局，以及离线退款跨重载保留和仅兑回一次。
