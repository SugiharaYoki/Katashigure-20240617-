# 伊什塔尔的赐福：可视化选择（BETA）

更新数据包并执行 `/reload`，进入「多功能菜单 → 竞技整备 → 伊什塔尔的赐福」，点击「共可分配四个槽位」后面的 **可视化选择(BETA)**。

## 界面与操作

快速整备把当前四槽、「全部」与十个职业筛选和装备按钮放在同一页。首次打开默认显示全部 38 件礼装，再次打开恢复上次浏览的筛选；每个职业最多五件礼装，采用固定的五列布局：

| 礼装名称（悬停看完整效果） | 统 | 纵 | 纺 | 解 |
| --- | --- | --- | --- | --- |
| 启礼「黄金圣果」 | 装备 | 装备 | 装备 | 装备 |
| 统礼「水晶聚能」 | 装备 | 装备 | 装备 | 装备 |

- **直接装备**：点击礼装右侧的「统／纵／纺／解」即可替换对应槽位。页面立即显示保存结果、更新四槽配置及绿色 `✓`，并保留当前筛选，方便连续配置。
- **全部页**：职业栏最前面的「全部」按职业顺序排列 38 件礼装，可滚动浏览。名称显示「职业 · 礼装」，每行保留四个直接装备按钮；装备保存、解锁确认或查看详情后返回仍保留全部筛选。
- **随时切换职业**：顶部「全部」和十个职业名称可直接点击，当前筛选以金色、加粗和下划线标明。选择职业只筛选列表，不更改已装备的礼装。
- **按需查看详情**：悬停礼装名称查看完整效果与连携说明；点击名称展开带物品图标的详情页。装备操作可以直接在列表完成。
- **解锁并装备**：未解锁名称标灰，右侧槽位标金。点击目标槽位后，确认页明确展示 50 SHD 费用、余额、目标槽位和将被替换的礼装；确认即永久解锁并装备，取消回到当前筛选。余额不足、数据不可用时不扣款、不改配置。
- **退出与返回**：底部「完成」直接关闭，顶部保留竞技整备与聊天版入口，也支持 Esc 退出。

| 从快速整备页面开始 | 所需点击 |
| --- | --- |
| 装备当前职业的一件已解锁礼装 | 1 次 |
| 切换职业后装备 | 2 次 |
| 解锁并装备当前职业的一件礼装 | 2 次，含费用确认 |
| 查看完整效果 | 悬停即可；独立详情页按需打开 |

主列表的礼装名称按钮宽 146 像素，四个槽位按钮各宽 36 像素；头部合并为一段文字，包含两行当前配置与两行筛选入口，宽度限制为 310 像素。职业页便于集中整备，全部页提供完整滚动列表。页面切换沿用 `after_action: "none"`，收到新页面前保留当前页面。

## 维护

实现位于 `data/skyblock/function/pvp/skywar/bless/setting/visual/`，通过内联 `dialog show` 构建，无需资源包；更新后 `/reload` 生效，目标版本为 Java 1.21.11（数据包版本 `[94, 1]`）。

礼装效果沿用聊天版 `bless.mcfunction`，图标和一句话摘要位于 `tools/generate_ishtar_catalog.py`。修改后运行：

```sh
python3 tools/generate_ishtar_catalog.py
```

生成的 `visual/catalog.mcfunction` 随数据包提交，包含全部 38 件礼装、完整说明、职业入口和四个直接装备按钮。聊天版与面板共用 `ishtar_bless_1` 至 `ishtar_bless_4` 及个人数据箱；免费解锁仍由 `bless_unlock_defaults` 处理。

所有交互使用 `IshtarMenu` trigger，由 `skyblock:tick` 每 tick 分发。`home` 恢复玩家的 `ishtar_ui_role`（`0` 为全部，`1`–`10` 为职业），`role` 构造完整面板，`quick_*` 构造筛选入口与礼装行。每次请求都重读当前玩家的解锁状态，`equip` 保存后返回当前筛选。共享 storage 只在单次同步函数调用中构造页面。

`unlock` 复用原有购买与数据箱写入逻辑，只有写入成功后才扣除 50 SHD；重复确认不会重复扣款。解锁并装备的确认编号直接编码礼装与目标槽位，过期页面不依赖另一次点击留下的选择状态。

打开聊天版菜单时先调用 `visual/init` 并启用当前玩家的 trigger，缺失的记分项可在入口自动补齐；重复调用不会重置四槽。`legacy_route` 兼容旧 `MultiMenu` 面板。`color_war/init` 的文本组件与 `pack.mcmeta` 已修复，保证本面板所依赖的加载初始化能够执行。

| 请求编号 | 行为 |
| --- | --- |
| `140000` | 打开／返回当前筛选的快速整备 |
| `140101`–`140104` | 兼容旧版目标槽位按钮 |
| `140200` | 全部 38 件礼装 |
| `140201`–`140210` | 切换职业筛选 |
| `140301`–`140338` | 可选的礼装详情 |
| `140401`–`140438` | 仅解锁的确认页，兼容详情入口 |
| `14SIII`，S=1–4、III=001–038 | 直接装备；未解锁时确认解锁并装备 |
| `14SIII`，S=5–8、III=001–038 | 确认解锁并装备到 S−4 号槽位 |
| `149001`–`149038` | 仅确认解锁 |
| `140997` / `140998` / `140999` | 聊天版 / 竞技整备 / 关闭 |

## 验证

使用完整仓库数据包与原始 load、tick 标签，在隔离的原版 1.21.11 服务端以普通玩家权限检查实际下发的页面与按钮命令。验证范围覆盖十个职业、38 件礼装的完整效果、152 个直接装备入口、四槽连续保存与职业保持、可选详情、取消购买、解锁并装备、重复确认、恰好 50 SHD、余额不足及越界编号。

「全部」页另完成 16 次普通玩家交互验证，检查首次默认展示、38 行礼装和 152 个槽位入口、11 个筛选入口与选中状态、职业名称及未解锁颜色、装备后保持全部筛选、详情返回、解锁取消与确认、重新打开时记忆全部或职业筛选。

此前也验证了完整重启和 `/reload` 的初始化、删除 `IshtarMenu` 后菜单入口自动补齐、四槽原有配置保留。完整包中其他旧功能仍存在兼容性报错，本轮验证范围为赐福面板及其加载入口。
