# 伊什塔尔的赐福：可视化选择（BETA）

执行 `/reload` 后，进入「多功能菜单 → 竞技整备 → 伊什塔尔的赐福」，点击「共可分配四个槽位」后面的 **可视化选择(BETA)**。

## 界面与操作

- **四槽总览**：顶部金色的四个按钮显示统、纵、纺、解当前的礼装。点击槽位，为它挑选礼装；下方两列按钮按 10 个职业展示全部 38 种礼装的分类入口。
- **职业礼装**：显示职业图标、定位、当前四槽和准备更换的槽位。已装备的礼装带 `✓`，未解锁的礼装明确标注「未解锁」；悬停可看简要作用，点击进入详情。
- **礼装详情**：显示物品图标、完整效果与连携说明。四个「装备到…」按钮直接替换对应槽位，悬停可查看将被替换的礼装。金色表示准备更换的槽位，绿色 `✓` 表示已经装备。
- **立即保存**：装备后留在详情页，显示「已保存」并刷新四槽，不需要额外确认保存。可继续选择其他槽位，或返回职业列表、四槽总览。
- **解锁礼装**：未解锁项显示 50 SHD 的解锁入口。确认页展示余额；解锁成功后返回详情，由玩家自行选择装备槽位。余额不足会明确提示，重复请求不会重复扣款。

按钮采用两列、每列 150 像素的布局；长说明由原版对话框滚动显示。支持 Esc 退出，保留返回竞技整备与聊天版菜单的入口。

切换页面和装备时会保留当前页面，收到服务器的新页面后再替换，避免停留在「等待服务器响应」。

## 维护

实现位于 `data/skyblock/function/pvp/skywar/bless/setting/visual/`。页面通过内联 `dialog show` 构建，无需资源包；更新页面后 `/reload` 即可生效。

礼装效果沿用 `bless.mcfunction`，图标和一句话摘要位于 `tools/generate_ishtar_catalog.py`。修改礼装后运行：

```sh
python3 tools/generate_ishtar_catalog.py
```

生成的 `visual/catalog.mcfunction` 随数据包提交。初始免费解锁逻辑提取到 `bless_unlock_defaults.mcfunction`，供聊天版和面板共同调用；两种界面共用原有四个礼装记分板与个人数据箱。

客户端按钮只发送独立的 `IshtarMenu` trigger，由 `skyblock:tick` 中的 `visual/tick` 每 tick 处理，不依赖旧聊天菜单的分发状态。`legacy_route` 兼容更新前已经打开、仍发送 `MultiMenu` 的旧面板。服务端每次交互都重新检查解锁状态；只有成功写入个人数据箱后才扣除 50 SHD。玩家的目标槽位、职业分别保存在 `ishtar_ui_slot`、`ishtar_ui_role`，共享 storage 仅用于同步构造当前页面。

| 编号 | 行为 |
| --- | --- |
| `140000` | 四槽总览 |
| `140101`–`140104` | 选择目标槽位 |
| `140201`–`140210` | 职业分类 |
| `140301`–`140338` | 礼装详情 |
| `140401`–`140438` | 解锁确认 |
| `14SIII`，S=1–4、III=001–038 | 装备到槽位 |
| `149001`–`149038` | 确认解锁 |
| `140997` / `140998` / `140999` | 聊天版 / 竞技整备 / 关闭 |

依据本地知识库的《对话框定义格式》《命令/dialog》《文本组件》《数据包/版本》实现，目标版本为项目 `pack_format: 94.1` 对应的 Java 版 1.21.11。

## 验证

在隔离的原版 1.21.11 服务端与协议测试客户端中验证了 105 次面板交互，检查实际下发的对话框数据，包括所有职业、38 种礼装的完整效果和四个装备按钮。另验证了四槽保存、两组个人数据箱解锁、重复购买、余额不足、恰好 50 SHD、越界编号拒绝、不同玩家的解锁隔离及读取 marker 清理。

针对槽位切换后停留在等待屏幕的问题，新增了独立请求入口，并在普通玩家权限下使用实际下发的按钮命令完成 37 次交互检查。测试同时运行原菜单分发流程，覆盖四个槽位的切换与目标提示、10 个职业入口、装备保存、购买确认和返回导航；另检查了返回竞技整备、聊天版菜单和关闭时都会显式清除对话框。
