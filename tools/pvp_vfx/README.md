# PVP 礼装特效 · 2026-11-16 第四版

适用 Minecraft Java 26.3，覆盖 1–39 号礼装。恢复立体造型、大范围展开和完整出招节奏；用每个玩家自己的镜头避让保留战斗视野。无需新增资源包。

## 视觉与视野规则

- 出招由八次脉冲组成：第 1、3、5、7、10、13、16、19 tick；动画实体在第 22 tick 删除（1.1 秒）。动画固定在释放地点，几何向外展开，不持续跟随玩家。
- 刀弧抬起形成立体掠斩；羽翼向两侧和后上方展开；落雷从高处落到地面；花莲分内外两层立起；甲片、晶簇、骨纹、锁链、冰刺和空间裂缝恢复高度。最大展开半径约八格，部分刀光与射线延伸更远。
- 第 3、5、7、10、13 tick 沿主轮廓叠加自发光亮芯，单次持续 6 tick（0.3 秒）；移动亮芒仍为 4 tick。细尘缩放 0.18–0.28，自身寿命约不超过 11 tick；末段快速消散。
- 取消整个 4–6 格近场禁区和统一眼高留白。每次绘制都按观众自己的眼睛位置与朝向放置四个瞬时检测点：眼前 0、1.5、3、4.5 格，半径分别为 1.15、1.15、1.25、1.35 格。只隐藏落在这些区域的粒子，侧面、脚下和远处保留。
- 每个观众同步绘制后立刻清理检测实体和临时接收标签。细尘仅发给当前观众；亮芯也只发给当前标记的观众。移动粒子另增加 0.75 格余量。没有异步调用或跨帧共享观众状态。
- 24 号三阶段蓄力不再被大范围近场隐藏，钻头入口增加向外崩裂的立体边缘；39 号恢复侧向加速门与蓄力弧，保留中轴空间。
- 常驻绕身光环、环绕物品和持续粒子笼仍保持关闭。私有提示只在触发时出现一次，不向旁人泄露隐身位置。固定陷阱、烟幕边界与明灯范围保留事件提示。
- 技能伤害、消耗、冷却、射程、建造、地图破坏及生存模式条件保留原指令。原有遮屏大标题、大团烟墨和药水装饰粒子保持关闭。

镜头避让发生在发送时，原版客户端中已经生成的粒子不能逐帧撤回。高速移动、快速转头或第三人称镜头仍可能短暂看到前一时刻的粒子；短粒子寿命用来减少这种残影。测试连接验证数据与接收范围，不代替真实客户端的视觉验收。

## 预览

游戏中 `/function pvpfx:showcase` 在前方六格依次展示 39 种释放效果，每种间隔两秒。可在创造模式观看，不调用攻击逻辑。

```mcfunction
/execute at @s positioned ^ ^ ^8 run function pvpfx:skill/24/cast
/execute at @s positioned ^ ^ ^8 run function pvpfx:skill/39/cast
/function pvpfx:cleanup
```

打开 `preview.html` 可选择礼装，观看动画阶段、旋转远景、切换第一人称并移动观察点检查镜头避让。这是坐标模拟，不是客户端截图；贴图、光照和音效以游戏为准。

## 维护与验证

`generate.py` 生成几何、音效、动画帧和预览，`generated.json` 记录生成文件；重建时会移除已退役的生成函数，保留手写事件文件。不要直接编辑生成函数。

```sh
python3 tools/pvp_vfx/generate.py
python3 tools/pvp_vfx/verify.py
```

`verify.py` 校验 39 技能接入、引用、寿命、逐观众镜头检测、爆发帧亮芯范围与临时实体清理、禁止遮屏粒子、无环绕实体以及战斗指令保留。`visual_changes.json` 逐条记录旧视觉的修改，只有粒子、文字和药水粒子隐藏开关可以豁免；没有宽泛忽略战斗逻辑。

`runtime_tests.py /绝对路径/测试世界/datapacks` 安装隔离测试包，禁止正式目录。执行 `pvpfx_test:all` 后读取 `storage pvpfx_test:result`。39 释放、全部钻头档位与充能阶段、三色灯域、箭矢识别、22 tick 生命周期和并发清理已有 302 项断言通过；原 24 号另有 85 项识别、蓄力、威力和破坏回归通过。40 个动画经真实 tick 推进后全部清理，临时亮芯与轨迹实体无残留。

`packet_probe.py /临时目录/结果.json` 只连接本机隔离端口 20101，使用三个无界面的 26.3 协议测试连接；逐包验证实际粒子接收距离和短轨迹参数。测试服需暂时关闭认证、压缩和必选资源包，并在结束后恢复；正式服务器配置不应修改。它不负责画面渲染，不能代替游戏客户端的视觉验收。 验证场景和实测数据见 `validation.json`；包含近处侧面/地面可见性、准星遮挡、不同朝向、全部释放、特殊发射器、私有提示、灯域和投射物。

测试服执行 `pvpfx_test:packet_positions` 设置三个观测点；探针输入 `reset 场景名`，再执行 `pvpfx_test:packet_casts`、`pvpfx_test:packet_private`、`pvpfx_test:packet_specials`、`pvpfx_test:packet_camera` 或 `pvpfx_test:packet_surfaces`。等三个连接均显示 `scenario complete` 后输入 `report` 保存，最后 `stop` 断开。

新逻辑只写 `pfx.*` 记分板、`PvpFx*` 标签与 `pvpfx:*` 存储。03、13、14、15 的物品标识沿用上一版，旧物品下次发放时带标。24 号实际攻击仍需满足原生存模式条件。

`packet_casts` 会把 40 个动画的全部帧压进一次控制台调用，用于完整接收核验；在隔离服触发过 10–15 秒的看门狗慢响应日志，调用最终完成。它不是实际 tick 播放的性能基准。真实 tick 清理另外验证，详见 `validation.json`。
